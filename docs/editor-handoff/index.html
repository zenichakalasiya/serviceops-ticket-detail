Support Portal Editor — how every part behaves

This page describes what the admin sees and what each control does, so you can build the editor without asking. The prototype is the reference: every screenshot here is taken from it. Where the prototype fakes something (dummy data, no backend), it is marked mock.

Audience: developersBehaviour only — no codeAs of 5 Oct 2026

What it is

The Support Portal is the page a requester (an employee) lands on to raise incidents, request services, approve things and read knowledge. The editor lets an ITSM admin — usually not a designer — build and style that page visually, then publish it.

An admin can keep several portals (for example one per company or department). Exactly one of them is live at a time: the default portal.

Design principleThe admin is not a designer. Every control should say in plain words what it does, show its result straight away on the page, and never be shown in a state where pressing it does nothing.

The mental model

Everything on a portal page is one of four things, nested in this order:

A section is a box that can be split; a column (or row) is a box inside it; a widget sits in a box. The same box can be split again, up to 4 levels deep.
  • Section — a full-width band. Can hold one widget, or be split into columns or rows.
  • Column / Row — a box inside a section. A box laid out side-by-side reads as columns; stacked, it reads as rows. Any box can be split again.
  • Widget — the content: a data card, an action card, text, an image, a button…
  • Child parts — some widgets have parts you can select on their own: a card's title, its View all link, its icon.
LimitsUp to 4 columns in a row and 4 levels of nesting below a section. Stacked rows are not capped. When a limit is reached, the Split control is removed from the toolbar rather than shown disabled.

  • Publish on a portal that is not the default opens a confirmation: "Publish “X” and make it the default?", naming the portal(s) that will go back to Draft. Choices: Publish and make default or Cancel (nothing changes).
  • Publish on the default portal goes straight through.
  • Save as draft on a published portal unpublishes it — the card shows Draft and the toast says it is no longer live.
  • The default can be switched off; it then becomes a Draft that is still the default.

Create a portal

The Create support portal button opens a two-step dialog.

  • The portal is created as a Draft the moment Step 1 is saved (toast: "… created — choose how to start it"). Leaving the editor never loses work.
  • Going Back to step 1 and saving again updates the same draft (the button reads "Save changes") — it must never create a second portal.
  • Start from scratch opens an empty page. Default (first tile, badged) is the standard ServiceOps layout. Templates are filterable by industry; each card shows up to two industry tags and a +N with the rest in a tooltip.
  • Portal names are unique; URLs are unique.

Edit details & Settings

Settings has nine collapsible groups in this order: Request · Service Catalog · Change · Asset · CMDB · Knowledge · Approval · Digital Signature · User. Request is open on arrival; the rest start collapsed.

  • Rows are switches, radio choices, numbers or chip selects.
  • A row that depends on another (e.g. Grace Period under "Allow requester to reopen") is removed when its parent is off — not greyed.
  • Search matches row labels and opens every group that contains a match.

Editor — screen anatomy

The editor takes the whole screen. The admin navigation is hidden; the back arrow is the way out.

Three places, one ruleCanvas = see it and pick it. Floating toolbar (appears on the selected item) = quick actions on it. Sidebar = all of its settings. A rail item opens a panel; selecting something on the canvas swaps the sidebar to that thing's settings.
  • The sidebar can be dragged wider from its left edge (min 340px).
  • Clicking the lit rail item again closes the panel.
  • The canvas renders the portal exactly as requesters will see it, using real layout — not a screenshot — so it reflows when the sidebar is resized.

Default page vs blank page

On the default page the predefined cards are ordinary sections, so they move, split and restyle like anything the admin adds.

Selecting things

  • Hover shows a light outline and a small name chip ("My Open Requests", "Section").
  • Click selects the innermost thing under the pointer: a blue outline, resize handles, the floating toolbar, and the sidebar switches to its settings.
  • To reach the thing around it (its column, its section), press Alt+↑; Alt+↓ goes back in. Esc deselects.
  • Inside a row of gathered cards, a card's toolbar has Select the row.
  • Text needs two clicks: the first selects its frame, the second puts the cursor in the words (see Editing text).

Resize handles

  • Width is a percentage of the parent (5–100%), so it follows the parent when the page resizes. Dragging an edge moves only that edge; the opposite edge stays put.
  • Between two side-by-side boxes, dragging the shared edge trades width between them.
  • Height is a real height; content that does not fit is clipped. The banner cannot go below 260px.
  • Top grip drags the gap above the element (never below 0 — sections never overlap).
  • On a section that holds several boxes, the side handles change the gap between columns and the bottom handle the gap between rows; the gaps show in pink while dragging, with a value badge.

Floating toolbar

Sidebar (settings of the selected thing)

Header: the element's icon and name, with a Reset (↺) on the right that returns that element to its default. Then up to two sections:

  • CONTENT — what it says and shows: titles, text, links, which records to list, the items of a list. Edits show on the canvas immediately.
  • DESIGN — how it looks, as collapsible groups. Order: shape first (Layout · Card templates · Banner), then look (Alignment · Background · Border & corners · Shadow · Icon), then Spacing, then Title placement. Expand all / Collapse all on the Design heading. Groups open independently (more than one can be open).
  • Live-data widgets (My Open Requests, Pending Approvals, My Assets, My CIs, Announcements, Most Read Knowledge) have no Content section — what they show is decided by the product, not the admin. They only have Design.
  • A setting that only applies in some state is removed, not greyed, when it does not apply (e.g. border colour only when border weight > 0).
  • Changing a setting that invalidates another resets the other and says so in a toast.

Sections & layout

Adding a section

  • Hovering a section shows + Add Section on its bottom edge; hovering the edge itself shows the blue line and a move grip. Shortcut N.
  • The new section is full width, directly below.
  • No section can be inserted between the banner and the Quick Actions row.

Splitting and adding columns

  • An empty column shows a grey +. A selected column shows blue + adders on its left, right (add a column) or top/bottom (add a row), depending on how its parent is laid out.
  • Adding a column makes all columns in that row equal width again.
  • Layout presets in a section's sidebar change its arrangement in one click (columns · grid · stacked; the set depends on how many items it holds).
  • Deleting the last item in a box removes the box; a branch left with one child collapses into it.

What can share a section

RulePredefined widgets (Data and Actions groups) and other widgets (Basic, Visual, Custom) never mix in one section. A drop that would mix them is refused with a toast saying why.

Widgets panel

  • Search on top, then tabs that jump to groups: Data · Actions · Basic · Visual · Custom. The tab follows as you scroll.
  • Predefined widgets (Data, Actions) can be on a page once. When placed, they leave the list and fold into "N on this page ›" on the right of their group title. A group with nothing left to add shows one line, "All added to the page". Searching always shows matches, folded or not.
  • Other widgets can be added any number of times.

Adding a widget — two ways

  • Drag from the widget's icon or name onto the page: onto an empty column, beside a widget (a blue line shows where), or onto the gap between two sections (creates a one-column section there). The panel stays open.
  • Click the + to add it: it goes into the selected empty column if there is one, otherwise into a new full-width section at the end. The panel stays open, so several can be added in a row.
  • Clicking the row's empty area does nothing — a slipped drag must never add a widget by accident.
  • Hovering a row opens a small preview card to its left: a sketch of the widget and one line about what it is for.

The banner

  • Adding a banner (from Widgets, when the page has none) asks the shape first — Horizontal (band across the top) or Vertical (a column beside the page) — then a layout, or Start from scratch.
  • Sections: the heading + search block is always one section. Picking 2, 3 or 4 adds empty cells, each with a + to choose what goes there (Announcements, Contact Us, KPI, Action Card, Quick links, Image, Text). Going down removes empty cells silently; if filled ones must go, a "Remove N sections" step lists them with checkboxes.
  • Arrangement tiles show where the sections sit (rows, columns, mixed). Widgets can also be dragged onto any edge of a banner section to make a new column or row there.
  • Action Card on the banner brings the whole set of four cards as one row; the page's Quick Actions row then stands down. Deleting the row brings it back.
  • Background (paint bucket): Image or Colour tabs. Colour is solid or gradient (any number of stops, angle). With an image, a colour layer (solid or linear gradient) sits between the picture and the words for readability. Double-click the banner to crop the image.
  • Height: drag the bottom edge; minimum 260px.
  • Banner layout in the sidebar shows the current layout and opens the same picker to change it.
  • A vertical banner can be pinned while the page scrolls; that only applies in Preview and on the live portal, never while editing.

Editing text

  • First click selects the text's outline. Second click (or Enter) puts the cursor in the words.
  • The formatting bar appears only while words are highlighted, floating just above them, centred on the selection (below them if there is no room above). It disappears when nothing is highlighted.
  • What it offers depends on how much is highlighted: some words get the word controls only; all of the text also gets Text style, Alignment and Placeholder, because those change the whole text.
  • Outline only (or a cursor with nothing highlighted): a placed Text widget shows its element toolbar — Drag · Replace · Copy · Alignment · Background · Delete. Text inside a predefined widget (Data and Action cards, the banner) shows no toolbar — only the bar on highlighted words. Text inside any other widget (e.g. a Custom Card title) shows Alignment only.
  • Using the bar or the colour picker does not end editing. Clicking anywhere else saves and ends it.
  • Headings and titles of cards are edited in place the same way, and also from the sidebar — both edit the same value.

Colour picker & spacing

Colour picker

  • Spectrum, hue and opacity rails, Hex · R · G · B · A fields, theme swatches, eyedropper where the browser supports it.
  • Light / Dark tabs: each colour has a light and a dark value; the picker opens on the mode the canvas is showing.
  • Changes apply live. Done keeps; Cancel restores the value it opened with (both modes).
  • "No colour" = opacity 0.

Spacing (Padding & Margin)

  • Each ring shows two fields: vertical (↕) and horizontal (↔), in px.
  • The chain icon links the sides. Breaking it opens all four sides of that ring.
  • Fields show the element's real resting value until set. Drag sideways on a field to scrub the value.
  • Hovering a field highlights that edge on the canvas in pink.

Theme

  • Theme style — 8 themes, one per colour family (Clarity is the default ServiceOps blue). Each sets the primary colour, a font pairing and button shape. Applying one is a single change and clears custom overrides.
  • Fonts — heading/body pairings, each shown in its own face.
  • Colours — tabs Primary · Secondary · Neutral, with a Light/Dark switch. Only Primary changes between themes; Secondary is the status language (green = good, red = broken) and Neutral is the greys.
  • Custom — page background, heading text, body text: overrides on top of the theme.
  • Tints across the page (badges, ID pills, tile fills) are derived from the primary colour, so changing it re-tints the whole page live.
  • The light/dark toggle in the top bar switches which version of the portal is being designed and previewed.

Branding

  • Portal name · Company (read-only) · Portal URL (read-only) · Support Portal title · Landing page for guest users · Sign-on (identity provider) · Contact shown on the portal (support email, phone).
  • The logo is edited by clicking it in the portal's top bar: upload (with a separate optional dark-mode logo, falling back to the light one).

Preview, Save as draft, Publish

  • The big button is always Publish. Its ▾ menu holds Save as draft.
  • Publish and Save as draft follow the Published / Draft / Default rules, including the "make it the default?" confirmation.
  • Publish has no keyboard shortcut on purpose (it changes what every requester sees). Ctrl+S saves as draft.

Undo, redo, reset

  • Undo / Redo (Ctrl+Z / Ctrl+Shift+Z) step through every change to the page, whichever surface made it. Disabled, with a tooltip, when there is nothing to undo/redo. Ignored while typing in a field.
  • Reset to default returns the whole page to its starting design.
  • Reset (↺) in the sidebar header resets only the selected element.
Known gap in the prototypeUndoing the delete of a predefined block (e.g. My Open Requests) does not bring it back. Production should restore it like any other change. Reset to default currently has no confirmation — production should ask.

Guided tour & Editor basics

  • The tour selects/opens what each step talks about and restores the previous selection when it ends. Close, Back, Next; Esc closes.
  • Finishing the tour opens Editor basics; skipping it does not.
  • Editor basics auto-plays through all chapters; picking a chapter loops it until the admin moves on. It has a full-screen button.

Notes for production

  • All data is dummy in the prototype mock. The live-data widgets must show the logged-in requester's real records, permission-filtered. Counts on badges are totals, not rows shown.
  • Save state: the prototype keeps everything in the browser session. Production must persist each portal's design per light/dark mode, its details and its settings, and keep Draft vs Published versions separate.
  • Destinations of the four Quick Actions cards and the "View all" links are product routes, not admin-editable.
  • URLs: default portal at the root address; others as a path under it. Validate uniqueness of name and URL.
  • Uploads: images (PNG/JPG/SVG/WebP), icons (SVG/PNG up to 512 KB), video (MP4 up to 5 MB). Enforce the same limits server-side.
  • Accessibility: every action reachable by keyboard; text on images needs enough contrast.
  • Switched off in the prototype (not part of this spec): toolbar move arrows, AI section builder, Advanced Tabs, Spacer, the Banners rail panel.
